- Files: `stay-with-us.html` (hero widget + Mews form submit buttons); doc comment updated in `overrides.css` §9f.

## 3. Bug fix: nav "Book a Stay" dropdown unreadable on Windows Chrome

**Symptom (reported by Nathan, confirmed by screen recording):** clicking BOOK A STAY in the top bar and opening the "Where" property dropdown showed a white popup with invisible entries — text only became readable on hover.

**Cause:** Windows Chrome paints `<select>` popups with the page's CSS (macOS uses native menus and ignores it, which is why it wasn't reproducible on Mac). The nav strip's select sets white text for the closed control; the options inherited that white text onto Windows' default white popup.

**Fix:** explicit option styling — options get an ink background (`#1F1F1F`) with white text; optgroup labels at 55% white. This mirrors what the Stay-page selects already did.

- File: `overrides.css` (`.nbp-field select option` / `optgroup`, §9e).

**Rule for the build — please treat this as a standing requirement:** any `<select>` rendered light-on-dark must declare explicit `option` and `optgroup` background/color. The dark widgets that need it: nav booking strip, homepage hero widget (both tabs), Stay hero widget, and the Mews form. `color-scheme: dark` alone is not sufficient on Windows in light mode.
